# NixOS on Oracle Cloud (Ampere A1, Always Free)

My NixOS config for a free Oracle Cloud ARM instance. It was installed over SSH from an Ubuntu image with [nixos-anywhere](https://github.com/nix-community/nixos-anywhere), uses [disko](https://github.com/nix-community/disko) for the disk layout and flakes for everything, and is deployed from my laptop with one command.

I'm learning NixOS on this server, so the config is deliberately small and commented. Write-up: [Day 1 with NixOS on Oracle Cloud (r/NixOS)](https://www.reddit.com/r/NixOS/comments/1xoz2pk/day_1_with_nixos_on_oracle_cloud_oci/)

## The machine

| | |
|---|---|
| Shape | `VM.Standard.A1.Flex`: 2 OCPU / 12 GB, the Always Free limit as of Nov 2026 |
| CPU | Ampere (Neoverse-N1), `aarch64-linux` |
| Disk | 46.6 GB paravirtualized boot volume (`/dev/sda`, virtio-scsi) |
| Firmware | UEFI, Secure Boot off |
| NixOS | 26.05 |

## Layout

```
.
├── flake.nix                        # inputs (nixpkgs 26.05, disko) → nixosModules.khakcsar + nixosConfigurations.khakcsar
├── flake.lock                       # pinned versions
├── hosts/
│   └── khakcsar/                    # everything specific to this machine
│       ├── default.nix              # boot, network, firewall, SSH, users, nix settings
│       ├── disko.nix                # GPT: 512M ESP (/boot, vfat) + ext4 root on /dev/sda
│       └── hardware-configuration.nix  # generated by nixos-anywhere on the server
└── services/                        # reusable modules, imported by hosts
    └── caddy.nix                    # Caddy serving a static page over HTTPS
```

`flake.nix` imports `./hosts/khakcsar` (a folder import loads its `default.nix`). The host imports the services it runs from `../../services/`.

### Public base + private deploy repo

This repo is the **public base**. It exports the whole system as a module, `nixosModules.khakcsar`. The apps I run on the server live in a separate **private** flake, which imports this one and adds its own services:

```nix
# private flake.nix (sketch)
inputs = {
  base.url = "github:designbyfaizi/nixos-config";
  nixpkgs.follows = "base/nixpkgs";            # one nixpkgs, controlled by the base
};
outputs = { nixpkgs, base, ... }: {
  nixosConfigurations.khakcsar = nixpkgs.lib.nixosSystem {
    system = "aarch64-linux";
    modules = [ base.nixosModules.khakcsar ./services/my-app.nix ];
  };
};
```

Deploys happen only from the private repo. Deploying `nixosConfigurations.khakcsar` from here would build the system *without* the private services, which would remove them from the server. This repo's own `nixosConfigurations.khakcsar` is there for reference, for `nix eval`, and for a fresh install.

## Highlights

- **systemd-boot** with `configurationLimit = 10`, so the 512 MB ESP never fills up. Every deploy is a boot entry you can roll back to.
- **`console=ttyAMA0`** keeps the OCI serial console (Cloud Shell console connection) working on ARM. It's the rescue path if SSH breaks.
- **SSH key-only**, root login disabled, `users.mutableUsers = false`. The user's password works only on the serial console. Its hash lives in a root-only file on the server (`hashedPasswordFile`), not in this repo.
- **Firewall** opens only 22/80/443. Apps listen on localhost behind Caddy.
- **zram swap** instead of a swap partition.
- **Caddy**: the site is built as a Nix package (`pkgs.writeTextDir`), so the page is part of each system generation, and HTTPS is automatic.
- **Housekeeping**: weekly `nix.gc` (older than 14 days) and `nix.optimise`.

## Installing (Ubuntu → NixOS)

Prerequisites:

- Nix with flakes on the machine you deploy from. Mine is x86_64 Arch, and nothing on it needs to be ARM.
- SSH access to the Ubuntu instance as a user with passwordless sudo.
- A boot volume backup, and the serial console tested, before you start.

Before installing, change the SSH key, username and hostname in `configuration.nix`. Create a placeholder hardware config so the flake evaluates:

```bash
echo "{ }" > hardware-configuration.nix && git add -A
nix eval .#nixosConfigurations.khakcsar.config.system.build.toplevel.drvPath   # sanity check
```

Then run the install. ⚠️ This wipes the disk.

```bash
nix run github:nix-community/nixos-anywhere -- \
  --flake .#khakcsar \
  --kexec https://github.com/nix-community/nixos-images/releases/download/nixos-26.05/nixos-kexec-installer-noninteractive-aarch64-linux.tar.gz \
  --generate-hardware-config nixos-generate-config ./hardware-configuration.nix \
  --build-on remote \
  -i ~/.ssh/<your-key> \
  ubuntu@<instance-ip>
```

- **`--kexec …nixos-26.05…`**: on my instance the **default kexec image hung**. Ubuntu kept running with its disk and network already shut down for the handover, and I had to force-reboot from the OCI console. The disk was untouched, because disko hadn't run yet. Passing the 26.05 installer image explicitly worked first time.
- **`--build-on remote`**: the system is built natively on the ARM server, so the x86 laptop doesn't need to emulate ARM.
- Afterwards: run `ssh-keygen -R <instance-ip>` (the host key changes), and log in as your new user.

## Day-to-day

Deploys run from the laptop through a small `justfile` in the private repo (`just check`, `just deploy`, `just test`, `just rollback`, `just gens`). Underneath, each recipe is `nixos-rebuild` from the **locked** nixpkgs, always with `--target-host`, so the laptop can never become the target:

```bash
nix run --inputs-from . nixpkgs#nixos-rebuild -- --no-reexec switch \
  --flake .#khakcsar --target-host khakcsar --build-host khakcsar --sudo
```

| Command | Effect |
|---|---|
| `switch` | Build on the server, activate, make it the boot default |
| `test` | Activate without making it the boot default; a reboot undoes it (for firewall/SSH/network changes) |
| `switch --rollback` | Back to the previous generation (nothing is built) |

To change the base: commit and push here, then in the private repo run `nix flake update base` and deploy.

## Oracle Cloud notes

- **Two firewalls.** A port must be open in the VCN **Security List** (ingress rule) *and* in `networking.firewall`. If `curl` times out, the cloud layer is blocking it. If it says *connection refused*, the packet got through and nothing is listening.
- **Always Free A1 is now 2 OCPU / 12 GB** (1,500 OCPU-hours and 9,000 GB-hours per month). Trial accounts can create bigger instances, so resize before the trial ends.
- **Idle reclamation:** Always Free instances with CPU (p95), network *and* memory all under 20% for 7 days may be reclaimed.
- The boot volume is attached as **paravirtualized virtio-scsi**. The `qemu-guest` profile and the generated hardware config (`virtio_pci`, `virtio_scsi`) are all that's needed to boot it.
